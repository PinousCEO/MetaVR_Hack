## B. Must be checked on the official rules page by the owner (NOT verified)

- [ ] Is an app that **requires a Windows PC companion** eligible, and how must judges get and install it? (This product needs the PC companion for its core experience; do not describe it as Quest-standalone.)
- [ ] Required build delivery: APK upload, release channel, store submission, or other. Required target devices and OS version.
- [ ] Mandatory SDKs or platform features (see the tooling hint above).
- [ ] Demo video: maximum length, hosting, what must be shown, language/subtitles. (A sub-3-minute scenario is in `reports/DEMO_SCENARIO.md`.)
- [ ] Submission language (the description in `reports/PROJECT_DESCRIPTION_EN.md` is in English).
- [ ] Rules on work created before the submission period, third-party assets, and disclosure of AI-assisted development (this code base was written with an AI coding agent; the character model was generated by the owner with Tripo from an AI-generated reference image and rigged in this project - check Tripo's licence for the plan it was made on and whether the rules require AI-generated assets to be declared; the typeface and UI art are made in the project).
- [ ] Use of a paid third-party AI service: voice conversation calls OpenAI (speech-to-text, a chat model, text-to-speech) with the owner's own API key. Check whether the rules allow it, whether it must be declared, and how judges are to try it: they would need a key of their own (`tools\Set-OpenAiKey.ps1`), or the demo video has to carry this part. Do not ship a key in the build or the repository.
- [ ] Whether a public or private repository link is required; what test credentials judges need. (Judges do not need a personal key: the reviewer sample uses a local git remote. Code analysis uses the judge's own Claude Code login, or the labelled stub mode.)
- [ ] Judging criteria and weights; one-entry-one-prize and team rules.

## C. Reviewer path that needs no personal repository or key

1. `Start-LivingPartner.ps1`, install the APK, pair, calibrate (RUNBOOK §1–§3).
2. `tools\Setup-Sample.ps1 -Open` creates the sample site with its own git history and a **local** bare remote.
3. Portal, hand ride, rain, timer: no account needed.
4. Analysis / code change: needs a logged-in Claude Code CLI on that PC. Without it the tasks fail with a clear message; `--stub-harness` exists only to demonstrate the flow and marks everything `TEST DOUBLE`.
