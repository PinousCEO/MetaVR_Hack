## Not implemented

- A wake word or always-on listening (by design: the microphone opens only when asked), and interrupting the partner while it speaks.
- Browser tab identity (window-level binding only).
- Spatial-anchor persistence of calibration (tracking-space epoch check instead).
- Tennis: sound, a difficulty setting, a second player. The court takes over the whole monitor while a game runs (the desktop is hidden behind it, input still passes through).
- Review: the revised picture is not shown inside the headset (the notes are; the picture and the PDF open on the PC). Follow-up questions about a file are answered from the notes taken while reading, not by reading it again. Scanned PDFs over 24 MB and other file types are refused.

Notes for whoever continues:
- Stop the running clients before building the Windows player (the build cannot overwrite loaded DLLs).
- Unity objects live in scenes and prefabs. To add or change something visible, edit it in the Hierarchy / Inspector, or change the layout values in `LPSceneBuilder` and re-run *Author Assets, Prefabs and Scenes* (it rewrites the prefabs and scenes, so hand edits to those files are replaced). Do not add `new GameObject` / `Find` / `GetComponent` to player code.
- `tools\Start-Dev.ps1` runs the host from `Companion\…\bin\Release`; `dist\LivingAIPartner-Host` is refreshed only by `dotnet publish` (see RUNBOOK §8).
- Do not call `EditorUserBuildSettings.SwitchActiveBuildTarget` in the same editor command as the APK build. Doing so through Unity MCP at 05:11 froze the Editor ("Hold on…") for 30 minutes; the process had to be ended and the project reopened, and the MCP relay then replayed the same queued command once more (it rebuilt the APK at 05:43 and froze again). To make any further replay fail harmlessly the build entry point was renamed from `LPBuild.BuildQuest()` to `LPBuild.BuildQuestApk()` (menu item unchanged). The Editor was reopened on the Windows target at 05:45; the APK from 05:43 is complete and has the same content as the 05:11 one.
- OpenXR's project validation throws a NullReferenceException inside `MetaQuestFeature` during the Android build; the build still succeeds (seen again at 12:05).
- To add a character design: add a `DesignSpec` in `LPSceneBuilder.DesignSpecs()` and its id to `Designs.Ids` (Shared), re-run *Author Assets, Prefabs and Scenes*, rebuild the host and both clients. To change a letter: edit its strokes in `StoryFontBuilder.Define()` and re-run the same menu; `Scenes/CharacterGallery.unity` shows the result (`GalleryCamera`, `SpecimenCamera`).
- Generated mesh assets are overwritten through the Mesh API (`LPSceneBuilder.CopyMesh`), not `EditorUtility.CopySerialized`: the latter kept the OLD vertex data when the vertex count changed, which showed up as a striped penguin face. `BuildPartner` now compares the saved vertex count with the definition and fails loudly.
- Text set from code must go through `StoryLabel` (`.text` or `.SetWrapped(text, widthInPanelUnits)`); widths are measured in the label's parent units so a panel that is still popping open wraps correctly.
- Runtime data lives in `%LOCALAPPDATA%\LivingAIPartner\` and can be deleted as a whole.
